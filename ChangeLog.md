## 2026-07-12 — Массовое обновление: перенос улучшений парсинга из BO

### core/sql_preprocessor.py — полная переработка препроцессора

**Новые шаги очистки (21 шаг вместо 7):**
- Удаление комментариев (`--`, `/* */`) с учётом строковых литералов (посимвольный обход вместо regex)
- Удаление Oracle hints: `/*+ ... */`
- Удаление outer join синтаксиса: `(+)`
- Удаление T-SQL batch separator: `GO`
- Удаление PL/SQL блоков: `CREATE FUNCTION`, `BEGIN...END`, `/` на отдельной строке
- Замена `<Procedure>` XML-блоков: `<Procedure name="..." type="...">` → `schema."name"` (имена сохраняются в `self.procedures`)
- Замена `TABLE()` функций: `TABLE(func(...))` → `func` (имена сохраняются в `self.table_functions`)
- Замена ODBC `{fn ...}` функций: `{fn NOW()}` → `CURRENT_TIMESTAMP`, `{fn CURDATE()}` → `CURRENT_DATE`
- Исправление незакрытых CASE: подсчёт CASE/END, вставка END перед клаузами
- Исправление неполных BETWEEN: добавление недостающих операндов
- Исправление обрезанных выражений: `IS` → `IS NULL`, `LIKE` → `LIKE ''`, операторы без правого операнда
- Исправление проблем CTE: пустой `AS ()` → `AS (SELECT * FROM dual)`
- Конвертация `IF(condition, true, false)` → `CASE WHEN ... THEN ... ELSE ... END`
- Удаление пустых скобок: `table_name()` → `table_name`
- Удаление лишних `)` и `AS` после алиасов подзапросов
- Балансировка несбалансированных скобок: вставка `)` перед клаузами или удаление лишних

**Оптимизации:**
- Скомпилированные regex для повторяющихся паттернов (производительность)
- Генератор `preprocess_stepwise()` — пошаговая обработка для прогрессивного парсера
- Логирование баланса скобок на каждом шаге

### core/parser_strategy.py — прогрессивный парсинг

**Новый класс `ProgressiveSQLGlotParserStrategy`:**
- Пошаговый парсинг: сначала сырой SQL, затем каждый шаг очистки по очереди
- Автоматическое исправление ошибок парсинга:
  - Несбалансированные скобки: вставка `)` перед ключевыми словами клауз
  - Незакрытый CASE: добавление END
  - Неполный BETWEEN: добавление недостающих операндов
- Запоминание применённых шагов (`last_applied_steps`) и очищенного SQL (`last_cleaned_sql`)

**Экспортируемые функции:**
- `_is_paren_error()` — проверка ошибки несбалансированной скобки
- `_is_case_error()` — проверка ошибки незакрытого CASE
- `_is_between_error()` — проверка ошибки неполного BETWEEN
- `_try_fix_case()` — исправление незакрытого CASE
- `_try_fix_between()` — исправление неполного BETWEEN
- `_try_insert_parens()` — вставка `)` перед клаузами

### core/parser_factory.py — поддержка прогрессивного парсера

- Добавлен тип `"progressive"` в `ParserFactory.create_parser()`

- Обработка `catalog.schema` для полного имени схемы таблицы
- Исправлен `_find_table_by_name()` — использование индекса вместо линейного поиска
