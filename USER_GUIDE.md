# Руководство пользователя SQL Metadata Parser v5.0

## Введение

SQL Metadata Parser — это инструмент для анализа SQL запросов, который автоматически извлекает метаданные: таблицы, колонки, алиасы, контексты использования и зависимости. Приложение имеет графический интерфейс на PyQt6, поддерживает 14+ диалектов SQL и предоставляет удобные средства для экспорта результатов.

### Что нового в v5.0
- **Прогрессивный парсинг** — пошаговая очистка SQL с автоисправлением ошибок
- **21 шаг препроцессинга** — обработка комментариев, Oracle hints, outer join, PL/SQL, CONVERT, ODBC и др.
- **Автоисправление** — незакрытые скобки, CASE, BETWEEN исправляются автоматически
- **Типы JOIN** — LEFT, RIGHT, INNER, OUTER отображаются в результатах
- **Типы таблиц** — таблица, CTE, подзапрос, процедура

## Установка и запуск

### Требования
- Python 3.10+
- Установленные зависимости из `requirements.txt`

### Установка
1. Клонируйте репозиторий или скачайте исходный код.
2. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```

### Запуск
Запустите главный скрипт:
```bash
python app.py
```

После запуска откроется главное окно приложения.

## Сборка исполняемого файла (EXE)

Для создания автономного исполняемого файла (EXE) используйте средства, расположенные в папке `for_exe`. Это позволяет запускать приложение без установки Python и зависимостей.

### Автоматическая сборка (Windows)

1. Перейдите в папку `for_exe`:
   ```bash
   cd for_exe
   ```
2. Запустите скрипт `build_exe.bat`:
   ```bash
   build_exe.bat
   ```
   Скрипт выполнит следующие действия:
   - Создаст виртуальное окружение (если отсутствует)
   - Установит все необходимые пакеты (PyInstaller, sqlglot, pandas, openpyxl, PyQt6)
   - Выполнит сборку с использованием spec-файла `SQLparser_hook.spec`
   - Скопирует готовый `SQLparser.exe` в корень проекта

3. После успешной сборки вы найдёте `SQLparser.exe` в корневой папке проекта.

### Ручная сборка (любая ОС)

1. Установите PyInstaller:
   ```bash
   pip install pyinstaller
   ```
2. Перейдите в папку `for_exe` и выполните команду:
   ```bash
   pyinstaller --clean --log-level INFO SQLparser_hook.spec
   ```

### Примечания

- Размер EXE-файла составляет около 140–150 МБ.
- По умолчанию EXE запускается с консольным окном. Чтобы скрыть консоль, измените `console=True` на `console=False` в `SQLparser_hook.spec`.

## Интерфейс приложения

Главное окно разделено на две основные панели:

### Левая панель — ввод SQL
- **Поле ввода SQL**: Вставьте или введите SQL запрос.
- **Кнопки**:
  - **Пример SQL**: Загружает пример сложного запроса (циклически переключается между примерами).
  - **Загрузить**: Загружает SQL из файла (`.sql`, `.txt`).
  - **Очистить**: Очищает поле ввода и результаты.
- **Переключатель подсветки синтаксиса**: Включает/выключает цветовую подсветку.
- **Выбор диалекта**: Oracle, PostgreSQL, MySQL, SQL Server, Snowflake.
- **Кнопка «Анализировать SQL»**: Запускает анализ.

### Правая панель — результаты парсинга
- **Общий фильтр**: Фильтрация строк во всех вкладках по введённому тексту.
- **Вкладки**:
  - **Колонки**: Полное имя, таблица, алиас таблицы, тип объекта, алиасы, места использования, количество упоминаний.
  - **Таблицы**: Схема, имя, алиасы, тип (Таблица/CTE/Подзапрос/Процедура), количество колонок, тип JOIN.
  - **Линедж**: Зависимости колонок и их использование.
  - **Статистика**: Сводная статистика по запросу.
  - **Текстовый вывод**: Текстовое представление результатов.
- **Кнопки экспорта**: CSV, Excel, TXT, JSON, копирование в буфер обмена.

### Верхняя панель
- **Чекбокс «Тёмная тема»**: Переключает между светлой и тёмной темой.
- **Кнопка «Справка»**: Открывает окно справки с тремя вкладками: Справка, ChangeLog, Руководство.

### Нижняя панель
- **Строка состояния**: Текущий статус, количество колонок, таблиц и ошибок.
- **Информационная метка**: Подсказки и сообщения о ходе работы.

## Примеры использования

### 1. Быстрый старт
1. Запустите приложение.
2. Вставьте SQL запрос, например:
   ```sql
   SELECT u.id, u.name, d.department_name
   FROM users u
   JOIN departments d ON u.dept_id = d.id
   WHERE u.active = 1;
   ```
3. Убедитесь, что выбран правильный диалект (по умолчанию Oracle).
4. Нажмите **«Анализировать SQL»** (или `Ctrl+Enter`).
5. Результаты появятся на правой панели.

### 2. Анализ сложного запроса
Нажмите **«Пример SQL»** для загрузки готового запроса с CTE, подзапросами, алиасами и агрегатными функциями.

### 3. Фильтрация результатов
Введите текст в поле **«Общий фильтр»** — строки во всех вкладках будут отфильтрованы.

### 4. Экспорт результатов
Используйте кнопки в нижней части правой панели:
- **CSV** — табличное представление колонок.
- **Excel** — многостраничный файл со всеми вкладками.
- **TXT** — текстовый вывод результатов.
- **JSON** — структурированные данные.
- **Копировать в буфер** — TSV формат для вставки в Excel.

### 5. Работа с «сложным» SQL
Прогрессивный парсер автоматически исправляет типичные проблемы:
- Незакрытые скобки → вставляются перед ключевыми словами клауз
- Незакрытый CASE → добавляется END
- Неполный BETWEEN → добавляется недостающий операнд
- Oracle hints `/*+ ... */` → удаляются
- Outer join `(+)` → удаляется
- PL/SQL блоки → отсекаются, остаётся только SELECT
- CONVERT → конвертируется в CAST
- @переменные → заменяются на заглушки

## Горячие клавиши

- `Ctrl+Enter` — запустить анализ SQL.
- `Ctrl+S` — экспортировать результаты в CSV.

## Часто задаваемые вопросы

### Может ли парсер обрабатывать вложенные подзапросы и CTE?
Да. CTE определяются как таблицы типа «CTE», подзапросы — как «Подзапрос». Колонки CTE/подзапросов разрешаются через маппинг алиасов.

### Что делать, если парсер выдаёт ошибку?
1. Попробуйте прогрессивный парсер — он автоматически исправляет многие проблемы.
2. Убедитесь, что SQL синтаксически корректен для выбранного диалекта.
3. Проверьте, нет ли неподдерживаемых конструкций.

### Как интерпретируются вычисляемые колонки?
Колонки с функциями (COUNT, SUM, AVG) или арифметикой помечаются флагом `is_calculation` с типом вычисления и исходным выражением.

### Можно ли анализировать несколько запросов одновременно?
Нет, анализируется один запрос за раз. Используйте UNION для объединения или анализируйте поочерёдно.
